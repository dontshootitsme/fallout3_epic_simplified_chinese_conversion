# 汉字显示层：为什么必须有注入代码，以及三条路线

这份文档只讲一件事：**把汉字写进插件（本仓库做的事）之后，怎么让它显示出来。**
结论提前说：**必须有一段代码在运行时改引擎的文字处理，没有纯数据的做法。**

## 1. 为什么"只写 GBK 字节进 ESM"必然乱码

辐射3（Gamebryo 分支，2008 年代码）的文字链路是**单字节**的：

1. 引擎从插件里读到的是一串 `char*`，**1 个字节 = 1 个字符**，没有任何"多字节字符集"分支
   （实测：所有字符串都是 cp1252 单字节 NUL 结尾，见 `format-notes.md`）。
2. 渲染时逐字节去字库取字形。辐射3 的字库（`.fnt` + 图集 `.tex/.dds`）是**按字节值索引的
   256 格网格（16×16）**：字节值 0–255 直接决定取哪一格。
3. GBK 汉字是 **2 字节**（首字节 0x81–0xFE，尾字节 0x40–0xFE）。原版引擎会把这两个字节
   **各自当成一个字符**去查那 256 格，结果落在 latin-1 高位区的那些空格/符号格上 →
   你看到的就是方块、空白、或莫名其妙的重音符号。而且因为字节数≠字符数，
   **换行、居中、字数裁剪也全都会错位**。

所以缺两样东西，缺一不可：

| 缺什么 | 必须谁来做 |
|---|---|
| ① 把「两个字节当一个字符」的读法 | 运行时注入代码（hook 文本处理） |
| ② 一个能放几千汉字的字库 + 索引方式 | 换掉/扩展 `.fnt`+图集，且必须配合同一段注入代码 |

**这两件事都没法用"只改数据文件"完成。** 字库文件在 `Fallout - Textures.bsa` 里，即使我们
重打包换上图集，原版 `.fnt` 格式和 256 格索引也装不下几千汉字 —— 装得下汉字的 `.fnt`
用的是扩展过的索引方式，原版引擎读不懂。

## 2. 「网上那些汉化补丁不用装 FOSE」是怎么回事

社区里辐射3 的汉化实测都还需要 FOSE。原文（知乎《辐射3 2024年非官方汉化更新》配套文）：

> 「基础中的基础，**汉化都是依靠 fose 插件 F3DC.dll 实现的**。……一是**内核汉化**，
> 通过插件**使游戏支持 936 编码**，汉化内容在 esp、esm；二是**外挂汉化**，
> 通过插件抓取屏幕输出的文本，替换成汉化的。」

注意 **936 就是 GBK**，与本仓库 `--encoding gbk` 对齐。两条路都是插件。那"不用装 FOSE"的
补丁是什么？按可能性排：

| # | 情况 | 怎么核实（一分钟） |
|---|---|---|
| 1 | **安装包把 FOSE/F3DC 静默装好了**，教程里没提 | 看游戏根目录有没有 `Data\FOSE\Plugins\*.dll`、`fose_*.dll`、`F3DC.dll`/`F3DC.ini` |
| 2 | **补丁自带改好的 exe**（老式做法，直接把双字节逻辑打进 exe），所以"不需要"FOSE | 看包里是否附 `Fallout3.exe`/`Fallout3HZ.exe`；这类包**改 exe 改得更狠**，比降级更激进。甲午包就是同时附「降级后的 1.7.0.4 exe」与「1.7.0.3 exe」二选一 |
| 3 | **代理 DLL 注入**：在根目录放一个假的 `binkw32.dll`/`dinput8.dll`，游戏加载它就等于装了注入器 | 看根目录 DLL 列表。你的根目录现在是**原版** `binkw32.dll`（338,944 字节） |
| 4 | 那个补丁其实是**辐射4 / 新维加斯**（引擎不同）或 **GOG 版**（GOG 的 exe 与 1.7.0.4 不同） | 看补丁说明里的适用版本 |
| 5 | 只做**运行时词典替换**（`FOZH`，Nexus 26653），号称支持 Steam/GOG/Epic | 它仍然要 FOSE（`Data\FOSE\Plugins\fozh.dll`）+ Stewie Tweaks |

**如果你把下载的那个汉化包留在盘上，把路径告诉我，我直接读它的文件列表 + DLL 导入表，
就能告诉你它到底注入什么、适配哪个 exe 版本。** 这比猜快得多。

## 3. FOSE 与"降级"是两件事，但绑定在同一个约束上

* FOSE 本身**不能让汉字显示**，它只是注入框架；真正干活的是 F3DC。
* 降级之所以被扯进来：FOSE 的加载器对 `Fallout3.exe` **整文件做 CRC 并查硬编码白名单**
  （源码 `src/fose/loader/main.cpp`：`switch(crc)`，表里最高只有 1.7.0.3 的
  `0xFE5B82AE`，default 分支直接报 `CRC = %08X` 未知版本），**没有 force/fallback 开关**。
  所以想用 FOSE 就必须让 exe 变成 1.7.0.3。
* 官方指引（fose.silverlock.org 原文）：*"Bethesda has released an update labeled 1.7.0.4 …
  Use a downgrader for compatibility with the script extender and plugins."*
  指定用的降级器 = Nexus **24913 Fallout Anniversary Patcher**，描述明写支持
  **Steam / GOG / Epic 的 GOTY 与普通版**，并且降级后 `Fallout3.exe` 会自动加载 FOSE。

**「不想动 Epic 装的这个 exe」和「不想降级」是两个不同的顾虑，解法不一样：**

* 顾虑是**「别弄坏我的正版安装 / 别影响 Epic 更新与云同步」**
  → **推荐 R1：把游戏整份复制成第二份（约 9GB），只降级那份的 exe。**
    Epic 那份一个字节都不动，随时能删；存档在 `My Games\Fallout3\Saves` 与安装目录无关。
    这是唯一能既用成熟内核汉化、又完全不碰正版安装的做法。
* 顾虑是**「不想运行来历不明的 exe 补丁」**
  → 走 **R3 自研注入器**（下面），只往游戏目录放一个我们自己写的 DLL，`Fallout3.exe` 保持原样。
    代价：需要先做逆向，工程量最大。

## 4. 三条路线

### R1 成熟运行时 + 本仓库文本（**最快能玩**）
1. 复制一份游戏目录 → 在那份上跑 Anniversary Patcher 降到 1.7.0.3；
2. 装 FOSE v1.3b2 + **F3DC**（双字节/936 编码）+ 中文字库 `GB_*.fnt` + 图集，
   `sFontFile_1..8` 指过去，`bInvalidateOlderFiles=1`（本仓库 `fo3zh ini` 会生成这份 ini）；
3. 文本用现成成品包，或**用本仓库 `patch` 产出的文件覆盖**（完全可控）。

已知遗留问题（社区报告，供预期管理）：获得任务时的任务名弹窗换不掉（词典路线限制）、
DLC 少量地名/武器名残留、装汉化后 Zeta 结局不触发爆炸/赏金猎人物品 CTD、
电台字幕要另装 Radio Subtitles、开场视频字幕要 BikMod、大显存字库会卡。

### R2 只做显示层最小改动，文本全部自研（**风格完全可控**）
显示层同 R1 的 ①②（这层绕不过），文本 100% 走本仓库管线。
好处是可以只汉化你在意的部分（比如先 UI + 物品 + 终端），随时 `--rollback`。

### R3 自研注入器，不降级、不用 FOSE（**唯一"不碰 exe"的路**）
在 `Data\` 或根目录放一个代理 DLL（如 `dinput8.dll`/`version.dll` 转发真 DLL），
用**特征码扫描**（不是硬编码地址）定位 1.7.0.4 里的字形查找 / 文本测量 / 换行函数，
把「按 1 字节索引 256 格」换成「按 GBK 码位索引大图集 / 动态字形缓存」。

* 优点：`Fallout3.exe` 一个字节都不改；特征码写对了还能同时兼容 1.7.0.3 与 1.7.0.4。
* 代价：要逆向 32 位 exe 的渲染路径；没有现成 F3DC 源码可抄；只能靠你自己反复进游戏验证。
* 现状：**尚未开始**。本仓库的文本层与它完全解耦，注入器做出来即可直接对接。

### 不推荐
* **只做词典式运行时替换**：任务名弹窗、长句、多义词都换不掉，覆盖率最低。
* **只换图集不注入**：见第 1 节，装不进 256 格索引。

## 5. 验收清单（显示层装好后按序走）

主菜单/字体是否正常 → 控制台能否输入并显示中文 → 物品名与描述 → 技能获得弹窗 →
笔记/书本（长文本换行是否正确，这是双字节最容易错位的地方）→ 终端机（含翻页）→
对话与玩家选项 → 电台字幕 → 5 个 DLC 各抽查一处 → 存档读写正常。
